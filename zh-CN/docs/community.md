Semantica 以开放方式构建，汇聚了来自众多领域的研究者、工程师和实践者的贡献。无论你是提交 bug、分享项目，还是审阅 PR：你都是这个生态系统的一部分。


## 获取帮助

- [GitHub Issues](https://github.com/semantica-agi/semantica/issues)：提交带有完整上下文的 bug 报告和功能请求。
- [GitHub Discussions](https://github.com/semantica-agi/semantica/discussions)：提问、分享想法，并讨论设计决策。
- [Pull Requests](https://github.com/semantica-agi/semantica/pulls)：浏览已有贡献，并提交你自己的贡献。
- [Security Issues](https://github.com/semantica-agi/semantica/security/advisories/new)：私下报告漏洞（切勿发布在公开 issue 中）。


## 社区准则

我们遵循[贡献者公约行为守则](https://github.com/semantica-agi/semantica/blob/main/CODE_OF_CONDUCT.md)。社区建立在四项原则之上：

- **尊重**：无论经验水平如何，都要以善意和耐心对待每一个人
- **包容**：欢迎所有背景、领域和方法
- **协作**：共同寻求更好的解决方案，而不是在方法上互相竞争
- **学习**：开放地分享知识，毫不犹豫地提问，并帮助他人成长

如需举报不可接受的行为，请以 `[CoC]` 前缀打开一个 GitHub issue。每份举报都会得到调查。


## 贡献方式

贡献没有唯一正确的方式。选择适合你技能和时间的路径：

### 代码

- 修复带有 [`good-first-issue`](https://github.com/semantica-agi/semantica/labels/good-first-issue) 标签的未解决 bug
- 添加新功能或集成
- 改进性能或重构现有模块

### 文档

- 修正指南中的拼写错误并提升表述清晰度
- 为 API 参考添加示例
- 编写领域特定的 cookbook 笔记本

### 测试

- 为未经测试的模块添加覆盖率
- 复现并确认已报告的 bug
- 提升测试在跨平台上的可靠性

### 社区

- 在 issue 和讨论中回答问题
- 审阅开放的 pull request
- 在 GitHub Discussions 中分享你的 Semantica 项目

完整的开发工作流参见[《贡献指南》](/contributing-guide)。
