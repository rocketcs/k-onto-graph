# 单文档流水线验证

输入：循上介介绍-无股东版.docx。

## 已验证

- 使用真实 PipelineBuilder 和 ExecutionEngine 执行 parse、split、extract、merge、validate、store 六个处理函数。
- DOCXParser 读取 47 个非空段落、1938 个字符，无表格。
- SlidingWindowChunker 生成两个块，长度为 1800 和 338 字符，重叠 200 字符。
- DeepSeek deepseek-v4-flash 实际调用生成结构化 JSON。当前 Semantica 封装不传递 thinking 参数，验证脚本通过其底层客户端显式禁用 thinking。
- 对实体原文子串、关系端点、证据原文子串和状态枚举进行校验；按实体原名和关系四元组精确去重。
- GraphSession 写入独立 ContextGraph，保存 graph.json 后重新加载，核对节点数量。
- 最终 19 个节点、17 条边，排除 1 个非逐字匹配实体。引擎报告六步完成、耗时约 6.56 秒。
- events.json 是真实引擎状态采样，快速步骤可能在两次采样之间完成；不是完整事件总线。

## 内容抽查发现

- 迪拜分院已运营、南宁分院建设中、永生岛规划状态符合原文。
- 模型将教育合作关系标为“已运营”，原文只陈述合作，不足以支持这一运营状态。
- 2000+ 家、30+ 家、6 家、2028 年等主要停留在 evidence 文本中，没有专用数量和日期属性。
- 五大特色的证据只有“重点发展5大前沿领域”，缺少具体学科标题；逐字证据校验不等于语义蕴含验证。
- 同一合作在重叠块中产生“合作”和“合作开设”两种关系，精确去重不能统一语义。
- “肿瘤医学硕士项目”被逐字匹配规则排除；原文为“肿瘤医学和长寿医学硕士项目”。说明严格子串规则会损失并列短语的合理展开。
- 定长分块可能截断句子；正式处理需要保留段落和标题上下文。

## 范围与限制

这是可复现的本地处理链路验证。没有接通网页上传、HTTP 任务 API、页面实时状态、生产数据库或向量索引。图谱是独立本地 JSON，未写入当前运行中的知识库。没有验证自由 DAG 编排、语义实体消歧、OCR 或断点恢复。

首轮模型调用返回空正文后终止；第二次因客户端参数位置不兼容失败；最终将 thinking 参数放到请求层后成功。另发现 retry_on_failure=False 不控制当前引擎的重试循环，验证脚本改用 default_max_retries=0。早期运行产物保留在相邻时间戳目录。

建议接入 UI 前先补齐数量、时间、状态字段和语义质量规则，再增加任务 API 与持久化状态；页面只能将实际完成的步骤显示为完成。
